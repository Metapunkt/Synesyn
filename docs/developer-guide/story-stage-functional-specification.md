# Story Stage functional specification

- **Status:** Implemented (steps 1–6 in `synesyn_client/addons/story_stage/`; rung 4 warm real-time factor and 3D presenter pending)
- **Date:** 2026-10-21 (updated 2026-11-01)
- **Audience:** an implementer who has this document, the ADRs it cites, and a Godot 4.7 project, and who does not have the current addon source
- **Companion decisions:** [ADR 0027](../architectural-decisions/0027-scenario-declares-its-stage-features.md) (scenario opt-in), [ADR 0029](../architectural-decisions/0029-story-stage-is-a-host-driven-component.md) (host-driven component), [ADR 0030](../architectural-decisions/0030-story-stage-motion-and-imagery-layers.md) (layers, cues, motion ladder), [ADR 0031](../architectural-decisions/0031-spoken-line-carries-its-resolved-voice.md) (scenario voice travels with the request)

This specification is the contract for `addons/story_stage`. The current addon in `synesyn_client/addons/story_stage/` has been refactored to match this specification through step 6 of [§19](#19-suggested-build-order): host/voice/imagery ports, per-stage character registries, `SubViewport` rendering, per-speaker audio buses driving rung-1 motion, `[STAGING]` cues, `[VIS_PORTRAIT]` frame sheets, rung-3 `Skeleton2D`/shader deformation, and `[STAGES]` topology. Rung 4 (live per-line video clips) remains gated on the FlashHead spike's warm real-time factor, and the 3D presenter remains a future implementation of `StoryStagePresenter`.

The pre-replacement addon's habits that must not return are listed in [What a replacement must not copy](#17-what-a-replacement-must-not-copy).

## 1. Purpose

Story Stage is a visual stage for a story told line by line. An application that can say "this speaker says this line" hands the stage a **host**. The stage asks the host for the lines, the scenario, the art folders, a voice, and which optional controls to show. It never reads an application's globals.

What the audience sees is a performed conversation:

- characters appear as portraits (authored sprites today; generated frames or clips when a scenario and host allow it)
- the current speaker is visible, and while they speak their portrait is in a talking state timed to the voice
- a dialogue box types the line
- a backdrop stands behind the cast, and may become a slideshow of images the host supplies
- optional installation behaviour (a lull protocol, ambient OSC cues) runs only when the scenario asks for it

The dialogue and the choice of speaker are generated by the application. The picture is authored unless a scenario opts into imagery layers. A replacement that only switches idle and talking loops will satisfy the compatibility contract and fail the ambition: the stage must be able to show that it is responding to the line, the voice, and the cues.

## 2. Compatibility contract

"Drop-in" means all of the following, without edits to ScenSyn, the story-log player, or the repository checks:

1. The addon lives at `synesyn_client/addons/story_stage/` and is enabled as a Godot plugin named **Story Stage**.
2. The only hard dependency is `synesyn_core`. The addon names no project autoload, no `class_name` declared outside itself, and no `res://` path outside itself. `utilities/checks/check_story_stage_boundary.py` must pass.
3. Every `class_name` the addon declares starts with `StoryStage`.
4. The public types, scene path, project setting, signals, methods and unique node names in [§4](#4-public-surface) keep the same names and signatures that existing hosts already call.
5. A throwaway Godot project that contains only this addon and `synesyn_core` can instance the stage, hand it a three-line host, and see all three lines reach `line_displayed`. `utilities/checks/story_stage_dropin_test.py` must pass.
6. The story-log player (`synesyn_client/playback/`) and `ScenSynStageHost` keep working without source changes: they already subclass `StoryStageHost` and call the methods listed here.
7. A scenario that declares none of the new sections looks as it does today: one shared stage, authored idle/talking loops, speaker selection only, no lull, no ambient, no slideshow.

Behaviour behind those names may change. File layout inside the addon may change. Process-wide static registries must not be reintroduced.

## 3. Runtime and packaging

| Constraint | Requirement |
| --- | --- |
| Engine | Godot 4.7, GDScript. Features added in 4.4–4.7 (look-at modifiers, spring bones, IK, ping-pong `SpriteFrames`) may be used. |
| Plugin | `synesyn_client/addons/story_stage/plugin.cfg` plus a no-autoload `synesyn_client/addons/story_stage/plugin.gd`. The plugin registers nothing global. A project uses the stage by instancing a scene. |
| Default host | Project setting `story_stage/default_host_script` (String, a script path). A stage opened by `change_scene_to_file`, which cannot be handed a host, loads that script if it extends `StoryStageHost`. Otherwise it uses a bare `StoryStageHost`, which shows an empty stage. |
| Art | Scenario sprites, backdrops and generated `.tres` files belong to the application. The addon ships only generic images and sounds. |
| Video | Godot plays Theora (`.ogv`) natively. Any generated clip is converted before play, or decoded to frames when a matte is needed. |
| Line endings | Source files use LF. |
| Script size | Follow the repository line-limit ratchet. Split by role (core, presenter, ports, UI) rather than growing one stage script. |

Typical use:

```gdscript
var stage := preload("res://addons/story_stage/scenes/story_stage.tscn").instantiate()
stage.host = MyHost.new()   # before add_child
add_child(stage)
```

## 5. Host port

`StoryStageHost` is the whole application boundary. Defaults describe a stage on its own: no session, no log, no voice, no art, no optional features. A host overrides only what it has.

### 5.1 Signals

| Signal | When the host emits it |
| --- | --- |
| `story_log_changed` | The array from `get_story_log_entries()` gained or lost entries. The stage re-reads it. |
| `voice_owner_changed(stage_owns_voice: bool)` | This stage, rather than another view, now speaks (or no longer does). |
| `phase_changed(phase: String)` | The story moved into another named phase (`SETUP`, `INCIDENT`, `RISING`, `CLIMAX`, `RESOLUTION`). Ambient sound uses this. |

### 5.2 Default host resolution

```
StoryStageHost.resolve_default() -> StoryStageHost
```

Load `ProjectSettings.get_setting("story_stage/default_host_script", "")` if it exists and extends `StoryStageHost`. Cache the instance for callers that were not handed a host (a stage opened by scene path). Do **not** share mutable art caches through this singleton. Art caches belong to the stage instance that asked.

### 5.3 Scenario

```
get_scenario() -> Dictionary
get_default_background_name() -> String
```

`get_scenario()` returns the parsed scenario: keys are lower-case section names (`"vis_story"`, `"lull_protocol"`, …) mapping to dictionaries of string values, plus top-level fields the application already puts there (`name`, `scenario_key`, `_collection_id`, `_scenario_name`, `default_background`, character lists). See [§7](#7-scenario-sections).

`get_default_background_name()` is the scenario's `default_background` without a `.png` suffix, or `""`.

### 5.4 Story log

```
has_session() -> bool
get_story_log_entries() -> Array
commit_local_line(sender: String, text: String) -> bool
get_local_speaker_name(peer_id: int) -> String
get_local_character_name() -> String
load_story_log(path: String) -> void
get_story_log_dir() -> String
```

`has_session()` is true while there is a story to show.

`get_story_log_entries()` returns dictionaries, oldest first. Each entry has at least:

| Field | Type | Required |
| --- | --- | --- |
| `sender` | String | yes |
| `message` | String | yes |
| `timestamp` | String, `YYYY-MM-DD HH:MM:SS` | no (replay pacing) |
| `timestamp_us` | int, monotonic microseconds | no (preferred replay pacing) |
| `stage_cues` | Dictionary or Array | no (see [§9](#9-cues)) |

Skip entries whose `sender` is empty, `_meta`, or whose `message` is empty.

`commit_local_line` returns `false` when this host does not take input, or when another participant is responsible. On success the host appends the entry and emits `story_log_changed`.

`load_story_log` replaces the current log. The stage then calls `replay_story_log()`.

`get_story_log_dir` is where a file picker opens. Default: `OS.get_user_data_dir()`.

### 5.5 Voice

```
create_voice() -> StoryStageVoice
stage_owns_voice() -> bool
set_stage_owns_voice(owns: bool) -> void
resolve_voice_name(speaker: String) -> String
get_save_recordings() -> bool
set_save_recordings(stage: Node, enabled: bool) -> bool
```

`create_voice()` returns a silent `StoryStageVoice` unless the host has a speech engine. ScenSyn and the player return a `syntree_voice` adapter when that service exists; that adapter is **not** part of this addon.

`resolve_voice_name` implements a scenario's voice overrides (one speaker spoken in another's voice). Return `speaker` unchanged when there is no override.

The voice id that name resolves to leaves with the speech request. The hub speaks a blank `voice.name` as `en-US-AriaNeural`. [ADR 0031](../architectural-decisions/0031-spoken-line-carries-its-resolved-voice.md) records the first-line failure this caused, and the rule that the resolved config is written onto the request before the hub body is built.

`set_save_recordings` returns `true` when consent also had to be sent to a remote service, after which the stage re-syncs.

### 5.6 Opening narration

```
get_opening_welcome_text() -> String
mark_opening_spoken_on_stage() -> void
reset_opening_spoken() -> void
clear_opening_for_loaded_log() -> void
```

The first Narrator line of a new session may be the welcome. A loaded log must not speak it afresh (`clear_opening_for_loaded_log`). Skip-welcome on the voice port also suppresses it.

### 5.7 Input and generation

```
get_player_auto_input() -> Object
is_ai_busy() -> bool
```

Auto-input is duck-typed: `is_available()`, `is_enabled()`, `set_enabled(bool)`, and signals `auto_input_changed(bool)` and `configuration_changed(bool)`. `null` means none. While it is enabled, the typed field is inactive.

`is_ai_busy()` drives a loading indicator so a wait is visible.

### 5.8 Optional application hooks

```
supports(feature: StringName) -> bool
attach_session_services(stage: Node) -> void
populate_settings(stage: Node) -> void
navigate(stage: Node, target: String) -> void
toggle_services(stage: Node) -> bool
close_services(stage: Node) -> bool
start_new_story_log(stage: Node) -> bool
request_render(stage: Node, kind: String) -> void
set_dual_window(enabled: bool) -> void
get_dialog_theme() -> Theme
```

`navigate` targets are `"story_log"` and `"landing"`. `request_render` kinds are `"background"`, `"portrait"` and `"prop_card"`. `toggle_services` returns whether a services panel exists, so the stage can hide its own settings. Dialogs the stage opens inherit no theme from a `Node2D`; `get_dialog_theme()` supplies one.

`attach_session_services` runs once the stage is ready. A host may add child nodes to the stage (ScenSyn adds `ScenSynStageSession`). The replacement must not assume those children exist.

### 5.9 Art folders

```
get_sprite_roots() -> Array[String]
get_generated_sprite_resource_path(root_path: String, char_dir_name: String) -> String
get_scenario_art_dir() -> String
get_backgrounds_dir() -> String
get_replay_backgrounds_dir() -> String
forget_cached_paths() -> void
```

Sprite roots are searched most specific first. Each root holds one folder per character slug, plus optional `_fallback/`. See [§8](#8-art-conventions).

`get_generated_sprite_resource_path` is where a `res://` root may cache a built `SpriteFrames` `.tres`. Return `""` to keep frames in memory (workspace / absolute roots must not write under `res://`).

`get_scenario_art_dir` holds `background/` and `<scenario>_title_screen.png`.

`get_backgrounds_dir` is the shared named-background library a `default_background` refers to.

`get_replay_backgrounds_dir` is optional images to preload into the slideshow when a log is replayed.

### 5.10 Capabilities the director may be told

ADR 0030 adds a report the host can pass to a model so it only writes cues the stage can show. A replacement should implement:

```
granted_capabilities() -> Dictionary
```

Default `{}` on the base host so existing hosts need not override it. Keys are layer names (`topology`, `staging`, `character_motion`, `vis_story`, `vis_portrait`) mapping to the granted rung or mode and a one-line reason when a request was stepped down. Emit this once after ready, and again if availability changes.

## 6. Voice port

`StoryStageVoice` is how the stage speaks. The addon ships a silent base. An application adapter (outside this addon) talks to a speech engine.

### 6.1 Signals

| Signal | Meaning |
| --- | --- |
| `speech_started(speaker: String)` | Audio began. Start the talking state and lip-sync. |
| `speech_finished(speaker: String)` | Audio ended. The line feed may advance. |
| `speech_paused(speaker: String)` / `speech_resumed(speaker: String)` | Transport |
| `ready_to_speak` | Setup finished; the opening may be spoken |
| `synthesis_completed(speaker: String, duration: float)` | Audio is ready; `duration` is seconds |
| `playback_finished(speaker: String)` | Playback ended at the device. The line feed waits on this. |
| `transcription_completed(text: String, error: String)` | Microphone result; `error` is empty on success |

`speaker` is the voice name the stage passed to `speak` (already resolved through `resolve_voice_name`). The stage maps it back to the logical speaker when a voice is borrowed.

### 6.2 Methods

```
attach(stage: Node) -> void
is_present() -> bool
get_skip_welcome() / set_skip_welcome(skip: bool)
refresh_roster(scenario: Dictionary) -> void
enable_character(speaker: String) -> void
should_speak(voice_name: String, text: String) -> bool
speak(voice_name: String, text: String, emotion: String = "neutral") -> bool
speaking_character() -> String
is_busy() -> bool
pause() / resume() / stop_all()
cancel_synthesis() / clear_synthesis() / clear_activity()
stop_welcome_narration() -> void
recover_stuck_speaker() -> String
get_lipsync_frames(voice_name: String, speaker: String) -> Array
health_lines() -> Array[String]
set_save_recordings(enabled: bool) -> void
create_recorder() -> Node
transcribe(audio_path: String) -> bool
```

Rules:

- Nothing else on the port matters until `is_present()` is true. The silent base returns `false`.
- `speak` returns whether the line was accepted. The stage still shows the text if it was not.
- `enable_character` must accept a human participant's name, so a loaded log can voice their lines.
- `get_lipsync_frames` returns `{ "time": float, "mouth_open": float, "mouth_shape": String }` keyframes. `time` is seconds from the start of the line's audio. An empty array means "no curve".
- `create_recorder` returns a node with `start_recording()` and an awaitable `stop_recording()` that returns the file path, or `null`.
- `recover_stuck_speaker` unsticks a speaker whose audio never reported finishing. Return who it was, or `""`.

### 6.3 Imagery port (new, required for the ambition)

Ship `StoryStageImagery` beside the voice port. The addon default is a null implementation that never produces images. A host that can render (ScenSyn over VIS_STORY and the hub) supplies a subclass.

```
class_name StoryStageImagery
extends Node

signal backdrop_ready(cue_id: String, texture: Texture2D)
signal portrait_frames_ready(character_id: String, frames: SpriteFrames)
signal line_clip_ready(line_index: int, path: String)

func attach(stage: Node) -> void
func request_backdrop(cue: Dictionary) -> void
func request_portrait_frames(character_id: String, source_roots: Array[String]) -> void
func request_line_clip(line_index: int, character_id: String, portrait: Texture2D, audio_path: String) -> void
```

The stage never waits on these signals. A late or missing result leaves the current rung on screen. Generation stays in the host; the addon owns the queue, the slideshow, the crossfade and the portrait swap.

`host.create_imagery()` may be added on the host with a default that returns the null port, so existing hosts keep compiling.

## 7. Scenario sections

A scenario is a `.txt` file with bracketed sections. A section `[X]` becomes `scenario["x"]` (lower-case). Presence is the opt-in. A section may switch itself off with `enabled: false`. Sections whose accidental start is worse than their absence (audio, hardware) require `enabled: true`.

```
scenario_section_enabled(key, default_enabled=true):
    section missing or empty -> false
    enabled flag (string) lowercased == "true"  (default of the flag is "true" if default_enabled else "false")
```

### 7.1 Sections a replacement must honour

| Section | Default without it | Behaviour |
| --- | --- | --- |
| `[LULL_PROTOCOL]` | off | Five-tier lull. Threshold keys: `tier0_slideshow_s` (10), `tier1_arcs_s` (45), `tier2_murmur_s` (90), `tier3_welcome_s` (180), `tier4_cycle_s` (240). Murmur lines may live in `scenario["lull_murmurs"]` as an array of strings. |
| `[VIS_STORY]` | off unless `enabled: true` | Slideshow of host-supplied images. The backdrop stands when off. |
| `[AMBIENT_SOUND]` | off unless `enabled: true` | OSC to SuperCollider. Keys: `host` (default `127.0.0.1`), `port` (57120), `base_intensity`, `mood_<phase>` for each phase. |
| `[PLAYER_AUTO_INPUT]` | off | Host may expose auto-input. The stage only reads `get_player_auto_input()`. |

Addresses the ambient bridge sends, fire-and-forget:

| Address | Arguments |
| --- | --- |
| `/scensyn/mood` | string mood, float intensity |
| `/scensyn/phase` | string phase |
| `/scensyn/turn` | int turn |
| `/scensyn/speaker` | string speaker |
| `/scensyn/duck` | float gain (`0.15` while someone speaks, `1.0` after) |
| `/scensyn/lull` | int tier, float elapsed seconds |
| `/scensyn/stop` | none |

### 7.2 Sections the new implementation adds

| Section | Default without it | Behaviour |
| --- | --- | --- |
| `[STAGES]` | one shared stage | Topology: one stage per character, which window or viewport each occupies |
| `[STAGING]` | speaker selection only | Director writes cues; the stage realises marks, gaze, light, `talking_big` by intensity |
| `[CHARACTER_MOTION]` | rung 0 | Highest motion rung wanted, and its settings |
| `[VIS_PORTRAIT]` | authored sprites only | Generated portrait frames or per-line clips from the scenario's own art |

Effective capability is the intersection of the scenario request, `host.supports()`, and runtime availability (hub, reachable ComfyUI, model). Step down one rung at a time until one works. Log the reason once. Report the grant through `granted_capabilities()`.

A scenario that adds none of these sections is indistinguishable from today's Ireti Okan: authored loops, one stage, no lull, no slideshow.

## 8. Art conventions

The application owns the files. The stage only knows the folders the host returns.

### 8.1 Character sprites

Under each sprite root:

```
<slug>/
  idle/          0.png, 1.png, …   required for a portrayed character
  talking/       0.png, …          required for a talking state
  talking_big/   optional; used when staging intensity is high
  <expression>-idle/
  <expression>-talking/            optional named expressions
  mouth/         rest.png, open.png, wide.png, round.png, lips_closed.png, teeth.png
                 optional viseme sheet for motion rung 1
_fallback/
  idle/ …
```

`slug` is `dir_slug(character_name)`. Frames are PNG, sorted by filename, looped. Default playback 5 fps is acceptable for authored loops; ping-pong (Godot 4.7) is preferred when it reads better. RGBA with a real alpha channel is the compositing mask for generated clips.

A speaker with no folder is not given a placeholder portrait. Draw them with the spectrum visualiser (or, in 3D, a neutral stand-in). Substituting art that happens to load is worse than declining: it looks like correct behaviour.

### 8.2 Backdrops

Resolution order, first success wins. A miss returns nothing and the current image stays.

1. Scenario frame folder: `get_scenario_art_dir() + "/background/"` with two or more PNGs, cycled.
2. Named background: `get_default_background_name()` in `get_backgrounds_dir()`.
3. Nothing. Do not load a black or title-screen placeholder just because it exists. Names in the blank list (`title_screen`) are skipped on a blind pick.

### 8.3 Slideshow images

The host (or imagery port) supplies filesystem or `res://` paths. The stage crossfades (~1.8 s). Advance on speaker change, not faster than once every 3 s, and on `notify_turn_started`. During lull, the queue may cycle on a longer interval (~6 s).

## 9. Cues

When `[STAGING]` is on, an entry may carry `stage_cues`. Cues name things. They never carry pixels, frames or file paths. The same log drives a 2D stage, a 3D stage or a replay.

One cue object, or an array of them:

| Field | Type | Meaning |
| --- | --- | --- |
| `speaker` | String | Character id |
| `target` | String | Character id or mark the speaker addresses or looks at |
| `expression` | String | Named expression from the character profile (`neutral`, `concern`, `delight`, …) |
| `intensity` | float 0..1 | Selects `talking_big`, scales motion and light |
| `gesture` | String | Named gesture from the profile |
| `mark` | String | Named position on the stage |
| `stage_id` | String | Which stage, when `[STAGES]` gives each character its own |
| `at` | float | Seconds from the start of the line's audio. `0` if omitted |

Timing is relative to the line's audio, never to wall-clock or frame counts. A presenter ignores a field it cannot show.

Without `[STAGING]`, the only cue is "this sender is speaking".

## 10. Line presentation

This is the behaviour the drop-in test and the story-log player depend on.

1. The stage reads `host.get_story_log_entries()` and shows each entry it has not shown, in order.
2. A new entry is noticed when `story_log_changed` fires, and again on a short watchdog (~0.5 s).
3. One line is on stage at a time (`is_displaying_message`).
4. Before display, strip a leading `Sender:` or the BBCode form `[font_size=16][b]Sender:[/b][/font_size]` from the message.
5. If `voice_on()` and the voice `should_speak` the resolved voice name (and this is not a skipped welcome), call `speak`. Hold the line until `playback_finished`.
6. Otherwise hold for typewriter duration plus `3.0 * read_pause_scale` seconds, but never less than `max(1.5 * min(read_pause_scale, 1), 0.05)`.
7. If synthesis reports a duration and the line is still up after that duration plus 20 s, recover: clear the display flag, call `recover_stuck_speaker`, continue. Lull speech is exempt.
8. Do not queue while `voice.is_busy()` or `is_displaying_message`.
9. `replay_story_log` resets the index to `-1` and starts again over the host's current array. A playback host paces by revealing entries (the array grows); the stage does not need to know that.
10. Emit `line_displayed` once the line is on stage.

Typewriter: characters appear over a short time with an optional blip. Auto-scroll the dialogue while speech plays. After a line, the box may fade if the host is idle.

Opening: when the voice is ready, if there is welcome text and skip-welcome is off and the opening has not been marked spoken, speak it as Narrator, then `mark_opening_spoken_on_stage`.

## 11. Motion

Motion is a ladder. A scenario asks for a highest rung. The stage grants the highest it can and keeps a working fallback.

| Rung | What moves | Where | When granted |
| --- | --- | --- | --- |
| 0 | Authored idle / talking / optional expression loops | Client | Always |
| 1 | Mouth and bob follow the **actual audio**; visemes if a `mouth/` sheet exists | Client, speaker bus (`AudioEffectCapture` or spectrum) | Default goal of a replacement, even without `[CHARACTER_MOTION]` |
| 2 | In-between and expression frames generated once from the scenario's sprites, blended by cue | Imagery port, before the performance | `[VIS_PORTRAIT]` and a host that can render |
| 3 | Blink, breath, head tilt by deformation and shaders | Client (`Skeleton2D`, CanvasItem shaders, 2D lights) | `[CHARACTER_MOTION]` asks for it |
| 4 | A generated talking clip per line | Imagery port + hub `render.comfyui` | `[VIS_PORTRAIT]`, warm real-time factor from the FlashHead spike: ≤1 with the voice, ≤3 if generated one line ahead, otherwise offline / replay only |
| 5 | Continuous streaming avatar | Not built | Reachable later behind the same imagery port |

Rung 1 is the minimum visible improvement over today's text-estimated curve. TTS currently plays on Master; a replacement puts each speaker on a named bus so capture and ducking are real.

`talking_big` is selected when staging intensity is high (default ≥ 0.7) and the folder exists. Do not leave that folder unused.

Keyword-scoring of prose to pick an expression is not the primary path. Prefer an explicit `expression` cue. A conservative fallback (a small closed list of words the scenario itself lists) is allowed; inventing emotion from unconstrained text is not.

Shared viseme names, used by 2D mouth sheets and 3D blend shapes:

| Name | Mouth |
| --- | --- |
| `rest` | Closed |
| `open` | Open |
| `wide` | Wide / smile |
| `round` | Rounded (`o`) |
| `lips_closed` | Bilabial (`m`, `b`, `p`) |
| `teeth` | Fricative (`s`, `f`) |

Map hub frames that still say `mouth_a` / `mouth_e` / `mouth_m` / `mouth_s` and `syntree_voice` names (`mouth_o`, `mouth_u`) onto this set in one place.

A late rung-4 clip never blocks the line. Keep rung 1 or 2 on screen.

## 12. Topology and presenters

The **core** owns the host, the line feed, cue timing, capability grants and provenance fields. It does not draw.

A **presenter** implements:

```
show_line(speaker, text, cues)
apply_cue(cue)
set_mouth(viseme, intensity)
set_gaze(target)
play_gesture(name)
set_talking(speaker, intensity)
```

Ship a 2D presenter that uses today's sprites, marks (`Marker2D`), lights and a `SubViewport`. A 3D presenter is a later implementer of the same interface (rigged character, `Marker3D`, `LookAtModifier3D`, spring bones, IK). The core does not change.

`[STAGES]` may ask for one stage per character. Each stage is a core plus a presenter in its own `SubViewport` or `Window`. Registries, sprite caches and the default host are **per stage**. Two stages in one process must be able to show different scenarios.

The default, when `[STAGES]` is absent, is one shared stage with every portrayed speaker.

Named marks replace computed pixel positions. A 2D stage scene defines `Marker2D` nodes; a 3D stage uses the same names on `Marker3D`.

The whole 2D stage renders inside a `SubViewport` so it can already appear as a surface in a 3D scene, or on a second display.

## 13. Character profile

`StoryStageCharacterProfile` is a Godot Resource:

| Field | Purpose |
| --- | --- |
| `id` | Stable id (display name is separate) |
| `display_name` | Shown in the dialogue box |
| `sprite_slug` | Folder name under a sprite root |
| `scene_3d` | Optional packed scene for a 3D presenter |
| `expressions` | Names that exist as `<expression>-idle` / `<expression>-talking` or as 3D blend shapes |
| `gestures` | Names the presenter can play |
| `viseme_map` | Optional override of the shared viseme set |
| `voice_name` | Default voice; host overrides still win |

Existing hosts that only pass a name keep working: the stage builds a profile from the sprite folder and the display name.

## 14. Provenance

A saved story log is a JSON array of entries ([§5.4](#54-story-log)). Beside `log.json` sits `log.provenance.json`.

Current sidecar (`synesyn_provenance_v2`), written by the application, not by the addon:

```
{
  "schema": "synesyn_provenance_v2",
  "scenario": "…",
  "session_type": "story_catalyst",
  "stage": {
    "collection": "cultural_narratives",
    "scenario_key": "stochastic_dreams",
    "scenario_name": "Stochastic Dreams",
    "default_background": "",
    "cast": ["Narrator", "The Child", …],
    "voice_overrides": { "The Child": "Narrator" }
  }
}
```

A v1 sidecar has no `stage` block. Playback still works: speakers without art are visualised; the player can pick a sprite folder by hand.

A replacement should record, on each log entry or in an extended `stage` block, which motion rung and imagery layer rendered the line (`motion_rung`, `imagery`, `stage_id`). The player then restages what the audience saw. Older logs without those fields play at rung 0.

## 15. Godot features to use

These are requirements on the new implementation, not suggestions.

| Feature | Use |
| --- | --- |
| Per-speaker `AudioBus` with `AudioEffectCapture` or `AudioEffectSpectrumAnalyzer` | Rung 1 from the real voice; duck ambient |
| `AnimationTree` `BlendSpace1D` / `BlendSpace2D` | Blend idle, talking, expression, intensity |
| `SpriteFrames` ping-pong (4.7) | Smoother authored loops |
| CanvasItem shaders; `PointLight2D` with normal maps | Blink, breath, panel glow, cue-driven light, dissolves |
| `Skeleton2D` + weighted `Polygon2D` | Rung 3 deformation of existing sprites |
| `SubViewport`, `Window`, `ViewportTexture` | Topology; second display; 2D stage as a 3D surface |
| `VideoStreamPlayer` (Theora) | Rung 4 |
| `AudioStreamPlayer.get_playback_position()` + `Tween` | Fire cues at `at` |
| Movie Maker mode | Frame-exact recording of a replay, as evidence of what the stage generates |

Bake in now for a later 3D presenter: the cue vocabulary, the presenter split, the profile Resource, the shared viseme set, named marks, audio-relative cue timing, and SubViewport rendering. Do not put pixel coordinates or 2D-only types in the core or in the log.

## 16. User-visible behaviour that must remain

- Hamburger menu lists only the features the host supports.
- Typed input commits through `commit_local_line` using `get_local_speaker_name`. A character chosen in another scenario must not be attributed (that is a host rule; the stage just sends the name the host gives).
- Microphone: record, transcribe, optionally auto-send.
- Voice transport: pause, resume, skip. Skip-welcome toggle.
- Loading indicator while `is_ai_busy()`.
- Confirmation dialogs use `get_dialog_theme()`.
- Dual-window toggle calls `set_dual_window`.
- Render buttons call `request_render` with the three kinds.
- Spectrum visualiser for speakers without art, including the opening Narrator.

## 17. What a replacement must not copy

These are present in the current addon and are not part of the contract.

1. **Process-wide static registries** on `StoryStageCharacter`, a static default host used as an art cache, or static background-manager state. Two stages in one process must not collide.
2. **Keyword-scored expressions** as the way the picture responds to a line.
3. **A mouth curve estimated only from the text**, once real audio is available.
4. **Leaving `talking_big`, expression folders, `process_ai_response` and `send_phase` unused** while claiming a responsive stage. Either wire them through `[STAGING]` / cues, or delete them.
5. **A placeholder backdrop that loads successfully when a scenario named no art.** Return nothing.
6. **Lull, slideshow or ambient running for a scenario that did not declare them.**
7. **Generation inside the addon.** Imagery is a port. The hub and ComfyUI stay behind the host.
8. **Streaming avatars on the critical path** of a live line (motion rung 5).
9. **A custom fine-tuned avatar model** unless the FlashHead spike shows identity loss that an adapter would fix.
10. **Standalone visual-novel mode** (`dialog_file`, title screen, scene manager). Removed on purpose in ADR 0029.

## 18. Acceptance

A replacement is drop-in when all of these pass against the **existing** hosts and checks, with the new addon in `addons/story_stage`:

| Check | Passes when |
| --- | --- |
| `python utilities/checks/check_story_stage_boundary.py` | No autoload, foreign class, or outside `res://` path |
| `python utilities/checks/story_stage_dropin_test.py` | Three scripted lines reach `line_displayed` in a project that has only this addon and `synesyn_core` |
| `playback_smoke.json` | The committed five-line fixture plays; the sidecar `stage` block is read; voice may stay off; no ScenSyn session services are created |
| `scensyn_story_stage_dump_logs.json` | The ScenSyn wrapper scene still mounts and dumps UI metrics |
| Manual: Ireti Okan with no new sections | Authored loops, default backdrop, no lull, no slideshow |
| Manual: Stochastic Dreams with its existing sections | Lull, `[VIS_STORY]` slideshow, ambient OSC as today |
| Manual: two stages in one window (once `[STAGES]` is granted) | Different speakers, no shared sprite cache collision |

A replacement meets the ambition when, in addition:

| Check | Passes when |
| --- | --- |
| Rung 1 | Talking intensity follows the speaker's audio bus, not a constant and not text alone |
| `[STAGING]` | A fixture log with `stage_cues` moves gaze, expression and intensity; `talking_big` plays at high intensity when the folder exists |
| `[VIS_PORTRAIT]` sheets | Offline frames blend between authored idle/talking; missing frames fall back to rung 1 |
| Rung 4 (if the spike's warm real-time factor allows) | A clip can play with a line without blocking it; alpha compositing uses the portrait mask or a declared matte |
| Provenance | A new log records `motion_rung` / `imagery`; the player restages them |
| `granted_capabilities()` | A scenario that asks for an unavailable rung is granted the next one, with one log line |

## 19. Suggested build order

1. Compatibility skeleton: host, voice (silent), line feed, 2D presenter, unique names, drop-in test, boundary check, playback smoke.
2. Per-stage registries and SubViewport. Confirm two instances do not collide.
3. Rung 1 (real audio bus) and the cue vocabulary under `[STAGING]`, including `talking_big`.
4. Imagery port; move slideshow and backdrop queue fully behind it; `[VIS_STORY]` as today through ScenSyn's host.
5. `[VIS_PORTRAIT]` sheets (rung 2) and optional rung 3 deformation.
6. `[STAGES]` topology.
7. Rung 4 if `utilities/spikes/story_stage_motion/` records a usable real-time factor.
8. 3D presenter, using the same cues and profiles.

ADR 0030 stays Proposed until the motion spike's results are recorded. This specification can be implemented up through step 6 without that result.
