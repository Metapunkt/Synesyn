LimboAI + Metapunkt System Affordances

Because every agent is a behavior-tree node with access to services (memory, tools, sensors, dispatcher, audit, etc.), you can bolt on new capabilities without touching the language-model prompt itself.

Below are the most useful affordances you now have—and concrete examples of what each enables.

1. Behavior-tree control over LLM output
  • Branch, loop, or short-circuit based on any BlackBoard value (mood, battery, user flags).
  • Example: have the agent switch from "teaching" to "question-asking" once it detects user boredom.
2. Multi-agent orchestration with shared short-term memory
  • Dynamically spawn extra specialists (e.g., a fact-checker agent) when conversation veers into uncertain territory.
  • Run structured debates or brainstorming sessions and fuse the answers.
3. Action-dispatcher tool calls
  • Agents can trigger arbitrary Godot or HTTP tools mid-conversation: grab weather, query a database, control in-game objects.
  • Lets you demo LLM-driven game AI ("describe the room then actually open the door").
4. Plug-and-play task modules
  • Drop a new *.gd task into limboai_tasks/ (e.g., "Detect Profanity Task") and reference it in the BT; agents inherit it instantly.
5. Memory tiers (short-term, long-term, audit)
  • Persist key facts between game sessions or across entirely separate scenes.
  • Example: "NPC remembers that the player lied yesterday and reacts differently today."
6. Sensor interface & environment events
  • Feed real-time world data (position, health, camera hits) into the BlackBoard; LLM can comment or act on it.
  • Perfect for immersive NPCs that react to what the player is actually doing.
7. Cost / token governance via Payments client
  • Throttle or deny expensive model calls at runtime, switch to a cheaper model for background reflection, or use summarization to trim context.
8. Thread-isolated SynTree calls
  • Each agent already uses a unique thread_name, which means you can maintain multiple parallel sub-conversations (private thoughts vs. spoken words) safely.
9. Introspection & self-evaluation loops
  • Add a BT branch that runs "CriticTask" after every 3 turns: agent critiques its last answer and stores a "self-score" to bias future tone.
10. Auditable event stream
  • Every tool call, memory write, and generated message is logged. Great for analytics dashboards, moderation, or replay-and-debug.
11. Hot-swap personas at runtime
  • Because persona is just a property under AgentDefinition, you can morph character personality on a trigger (e.g., "player gave the NPC a gift → switch to friendly persona resource").
12. External knowledge injection
  • A new Tool can fetch vector-DB passages or game-lore YAML, then stuff results into short-term memory before the next LLM tick—achieving retrieval-augmented generation without rewiring prompts.
13. Time-driven or event-driven speech
  • The should_speak flag plus timers already give you turn-taking; expand that so agents speak only when they detect proximity or when the player waves.
14. Role-based security & capability caps
  • Want a "rogue" agent that can read but not write memory? Just wrap its BT with permission-check decorators.
15. Cross-scene persistence via Godot Resources
  • Save an AgentInstance as a .tres; reload it in a totally different minigame with its memories intact.

The Complete Picture

Put simply: LimboAI supplies deterministic control flow & services, Metapunkt wires that to powerful tools, and the LLM supplies the language.

Mix those three knobs and you can graduate from "chatting NPC" to:

  • Societies of NPCs that plan the economy while the player sleeps.
  • A guided-tour agent that walks around a level, triggering doors, lights, and narration.
  • Real-time design assistant that prototypes levels inside Godot by issuing engine commands.
  • Educational dialogue where a tutor spawns a "quiz-maker" sub-agent and a "score-keeper" agent.

Whatever conversational mechanic you imagine, you now have the scaffold to bolt it on—without prompt spaghetti.

Metapunkt - SLOP-Native AI Agent Orchestrator

Metapunkt is a sophisticated AI agent orchestration system for Godot that implements the SLOP (Simple Low-Overhead Protocol) for managing AI agents with different roles, capabilities, and decision-making systems.

Features

Multi-Agent Orchestration

Run multiple AI agents with different roles simultaneously

SLOP Protocol

HTTP-based communication for external agent interaction

LimboAI Integration

Behavior trees and state machines for agent decision logic

Tool Integration

Modular tool system including SynTree AI assistant integration

Role-Based Permissions

Agents can have specific roles with restricted capabilities

Persistent State

Resource-based configuration and state management

Quick Start

1. Enable the Plugin

Enable "Metapunkt" in Project Settings → Plugins

2. Create an Agent Definition

# Create a new AgentDefinition resource
var agent_def = AgentDefinition.new()
agent_def.agent_id = "my_agent"
agent_def.agent_name = "Agent-Helper"
agent_def.persona = "A helpful assistant that focuses on development tasks"
agent_def.role = "developer"
agent_def.logic_type = "limboai"
agent_def.required_tools = ["SynTree", "GodotUtils"]

3. Register and Spawn Agent

# Register the agent definition
AgentRegistry.register_agent_definition(agent_def)

# Spawn an agent instance
var agent = AgentManager.spawn_agent("my_agent")

Agent Roles

Developer Agents

  • Agent-Alexander: General development agent inspired by Christopher Alexander
  • Focus on systematic thinking and pattern recognition
  • Can modify code, analyze projects, use SynTree AI capabilities

Roleplay Agents

  • Agent-Chaplin: Character roleplay agent inspired by Charlie Chaplin
  • Focus on staying in character and providing engaging interactions
  • Read-only access, cannot modify codebase

Tool Integration

SynTree Integration

Agents can access SynTree's AI capabilities:

# Chat with AI assistant
var result = await agent.use_tool("SynTree", {
    "operation": "chat",
    "message": "Help me debug this function"
})

# Analyze code content
var analysis = await agent.use_tool("SynTree", {
    "operation": "analyze_content", 
    "content": "func my_function():\n\tpass",
    "type": "code"
})

Architecture

  • Core/: Agent management, orchestration, and decision logic
  • Networking/: SLOP server for external communication
  • TaskManager/: Asynchronous task execution system
  • Integrations/: Tool interfaces (SynTree, GodotUtils, etc.)

SLOP API

Metapunkt exposes a REST API for external agent interaction:

# List available agents
GET /agents

# Execute agent action
POST /agents/{agent_id}/execute
{
    "action": "use_tool",
    "tool": "SynTree",
    "args": {"operation": "chat", "message": "Hello"}
}

For more details, see the full documentation.

Conversational Agents Quick-Start

The Chaplin UFO demo (addons/test_chaplin_ufo_conversation.gd) is a fully-working template you can copy. Below is the distilled recipe.

1. Create Behaviour-Tree Asset

Use LimboAI's editor to make a tree that triggers three custom tasks shipped in addons/metapunkt/limboai_tasks/:

Task Purpose
SimpleConversationTask Generate the next utterance through SynTree and write it to shared memory
SetMemoryTask Flip should_speak flags to control turn-taking
CheckMemoryCondition Guard-node that checks should_speak before speaking

Save the tree as res://addons/metapunkt/behavior_trees/your_conversation.tres.

2. Define Agents

var believer_def := AgentDefinition.new()
believer_def.agent_id = "believer"
believer_def.agent_name = "UFO Enthusiast"
believer_def.persona = "An excitable stargazer convinced aliens visit Earth."
believer_def.role = "roleplay"
believer_def.logic_type = "limboai"
believer_def.logic_config = {"path": "res://addons/metapunkt/behavior_trees/your_conversation.tres"}

var skeptic_def := believer_def.duplicate()
skeptic_def.agent_id  = "skeptic"
skeptic_def.agent_name = "UFO Skeptic"
skeptic_def.persona   = "A calm scientist demanding hard evidence."

3. Spawn Agents & Shared Memory

var believer  = await agent_registry.create_agent_from_definition(believer_def, "user")
var skeptic   = await agent_registry.create_agent_from_definition(skeptic_def,  "user")

# Conversation metadata
short_term_memory.set_memory("conversation_log", [], "shared")
short_term_memory.set_memory("should_speak", true,  believer.agent_id)  # believer starts
short_term_memory.set_memory("should_speak", false, skeptic.agent_id)

4. Kick-off

Just enable the agents' behaviour trees (AgentManager handles the tick loop). When SimpleConversationTask runs, it builds a prompt like:

Your persona: A calm scientist demanding hard evidence.

Recent conversation:
<previous messages>

Respond directly to your conversation partner …

The task appends the generated text to conversation_log and flips the should_speak flags—giving you automatic turn-taking.

5. Live Logging (UI optional)

_process() in the Chaplin demo shows how to stream new messages to a RichTextLabel. Remove the recap loop if you only want live output (already done).

Service Reference Additions

Service Path What it does
ShortTermMemory addons/metapunkt/Memory In-memory key/value store with per-agent or shared scopes
ActionDispatcher addons/metapunkt/Core/ActionDispatcher Routes tool calls; SynTree, web requests, etc.
AuditLogger addons/metapunkt/Audit Structured JSON log of all agent events

These are auto-wired by _initialize_metapunkt() in the demo scene; reuse that helper or copy the module-assembly code.

Tips for Advanced Scenarios

  • Spawn a Critic agent that reads conversation_log every N turns and injects feedback.
  • Replace SimpleConversationTask with your own task that calls arbitrary REST APIs mid-sentence and feeds the result back to the LLM.
  • Gate expensive model calls by wrapping tasks in CheckMemoryCondition nodes that sniff a "budget_remaining" variable.
